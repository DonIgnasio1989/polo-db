## ⚠️ Главное про data/vin-db.json

**В поставке приложения файла `data/vin-db.json` НЕТ — и это намеренно.**
Боевая база оснащения живёт на вашем сервере; архив не должен её затирать.
Если после какого-то деплоя оснащение («📋 Оснащение (PR)») пропало — проверьте,
что на сервере остался ваш прежний `data/vin-db.json` с полными записями,
и восстановите его из резервной копии.

Локально, без боевой базы, приложение подхватывает `data/vin-db.example.json`
(пример формата с одной полной записью) — исключительно чтобы пощупать кнопку «Оснащение (PR)»;
в модалке при этом висит пометка «Загружен пример данных».

## Формат полной записи (для генерации боевого vin-db.json)

Исходные `.txt` дампа (пути в `filtered-files.txt`) остались на машине, где делался прогон.
Запустите генератор по тому же входу и положите результат в `data/vin-db.json`:

```json
{
  "vin": "WVWZZZ6NZYX123456",
  "engine": "AEX",
  "gearbox": "085",
  "gearbox_code": "CHL",
  "paint": "J2",
  "roof_color": "J2",
  "equip_code": "41",
  "prod_date": "1999-04-14",
  "pr": ["0EA", "1ZB", "G0C"]
}
```

Допустим старый вариант со склейкой `trim` (`"J2J241"` = кузов J2 / крыша J2 / оснащение 41) —
приложение разбирает оба формата (`vinDbColors`).

Описания PR-кодов: `data/pr-codes.json` (1 723 кода, боевой).
После появления полного vin-db.json заработают:
- автозаполнение мотора/КПП/краски/даты при добавлении VIN и в «✎ Уточнить данные»;
- «📋 Оснащение (PR)» с группировкой по категориям и живым фильтром;
- PR-коды на персональной наклейке в «📍 Где коды».
