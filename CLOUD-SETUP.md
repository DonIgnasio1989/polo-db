# ☁️ Облачная синхронизация «Базы Мастера» — настройка за 15 минут

Версия 1.14.0 добавляет вход по **нику + паролю** и серверное хранение данных на
бесплатном [Supabase](https://supabase.com). Приложение по-прежнему работает
офлайн и без настройки — облако включается, только когда заполнена конфигурация.

## Что синхронизируется

| Данные | Кому видно | Хранение |
|---|---|---|
| 🚗 Гараж (машины, VIN) | **только владельцу** (на всех его устройствах) | `user_data.garage` |
| 🛠 ТО / пробег по VIN | только владельцу | `user_data.to` |
| 📖 Журнал работ | только владельцу | `user_data.logs` |
| 🛒 Список покупок | только владельцу | `user_data.shop` |
| 👤 Профиль, статусы/избранное позиций | только владельцу | `user_data.profile`, `user_data.pflags` |
| 🔧 Правки каталога: заметки, цены, ссылки, история цен, фото позиций | **всем** | `part_overrides` + Storage |
| ➕ Добавленные позиции каталога | всем | `parts_custom` |
| 🔧 Добавленные сервисы/мастерские | всем | `workshops_custom` |
| 📐 Схемы узлов (фото + маркеры) | всем | `schemes` + Storage `bm-photos` |
| 🧑‍🤝‍🧑 Голоса за аналоги | всем (агрегат) | `votes` |
| 📁 Свои категории/разделы и их оформление | всем | `meta_shared` |

Правила слияния: last-write-wins по `updated_at`; гараж/журнал/список покупок
сливаются **поэлементно** (по id / VIN), поэтому параллельная работа двух
устройств не теряет записи. Офлайн-правки уходят на сервер при первом же
онлайне. Общие таблицы обновляются у всех вживую (Realtime).

## Шаг 1. Создайте проект Supabase

1. Зарегистрируйтесь на <https://supabase.com> (бесплатно, можно через GitHub).
2. **New project** → имя (например `polo-db`), пароль БД (сохраните), регион
   поближе (например Frankfurt/London) → Create.
3. Дождитесь инициализации (~2 минуты).

## Шаг 2. Примените схему БД

1. В дашборде проекта: **SQL Editor** → **New query**.
2. Вставьте всё содержимое файла [`supabase/schema.sql`](supabase/schema.sql) → **Run**.
3. Проверьте: **Table Editor** показывает таблицы `profiles`, `user_data`,
   `parts_custom`, `part_overrides`, `workshops_custom`, `schemes`, `votes`,
   `meta_shared`; **Storage** — публичный бакет `bm-photos`.

## Шаг 3. Отключите подтверждение email

Вход в приложении — по нику (почта фиктивная, письмо отправить нельзя):

**Authentication → Sign In / Providers → Email → Confirm email = OFF → Save.**

Там же убедитесь, что минимальная длина пароля — 6 (по умолчанию так и есть).

## Шаг 4. Впишите ключи в js/cloud.js

**Project Settings → API** скопируйте *Project URL* и *anon public key*, затем
в начало [`js/cloud.js`](js/cloud.js):

```js
const CLOUD_CONFIG = {
    url: 'https://XXXXXXXX.supabase.co',
    anonKey: 'eyJhbGciOi…'   // публичный anon-ключ — он и должен быть публичным
};
```

> anon-ключ не секретен: все операции защищены RLS-политиками из schema.sql.
> `service_role`-ключ в клиентский код класть **нельзя никогда**.
>
> Для локальной отладки конфиг можно переопределить без правки файла:
> `localStorage.setItem('vw_cloud_cfg', JSON.stringify({url:'…',anonKey:'…'}))`.

## Шаг 5. Задеплойте новые файлы в репозиторий

Скопируйте в `DonIgnasio1989/polo-db` (структура путей важна):

```
index.html          (изменён: лоадер, меню ⚙️, модалка cloudmo, индикатор)
css/app.css         (дописан блок стилей 1.14.0 в конце)
js/app.js           (изменён: хуки cloudMark, afterBoot в lAll, версия)
js/cloud.js         (НОВЫЙ — с заполненным CLOUD_CONFIG)
js/supabase.js      (НОВЫЙ — supabase-js v2 UMD, грузится лениво)
data/update.json    (1.14.0 + changelog)

```

⚠️ **sw.js** (service worker) в поставку не входил — если в нём есть список
precache-файлов, добавьте `js/cloud.js` и `js/supabase.js`, иначе офлайн-вход
может не сработать. Runtime-кэширование менять не нужно.

После публикации: откройте сайт, меню **⚙️ → ☁️ Облако · вход и синхронизация**,
зарегистрируйте первый ник и проверьте на втором устройстве/браузере.

## Как это работает внутри (кратко)

- **Вход без email**: ник приводится к фиктивной почте
  `ник@users.baza-mastera.app` — Supabase Auth сам обеспечивает уникальность
  ника, хэширование пароля (bcrypt) и JWT-сессии. Восстановления пароля нет —
  это осознанный компромисс входа «без почты».
- **Ленивая загрузка**: `js/supabase.js` (218 КБ) скачивается только когда
  в localStorage есть след сессии или пользователь открыл форму входа —
  анонимные посетители не платят трафиком.
- **Хуки в app.js**: каждая функция сохранения (`sG`, `sD`, `sWk`, `sLogs`,
  `_toPersist`, `sShopPick`, `sMeta`, `schSet`, `setVote`, `iPut/iMany/iDel/iClr`)
  вызывает `cloudMark(kind)`; облако помечает вид данных «грязным» и через
  1.2 с отправляет на сервер. Без входа `cloudMark` — no-op.
- **Общие vs свои позиции каталога**: app.js сообщает облаку, какие позиции
  пришли из справочных `data/parts-*.json` (`Cloud.setServerParts`); всё, чего
  там нет, считается пользовательским и уезжает в `parts_custom`.
- **Фото**: base64-фото (схемы, позиции) при первой синхронизации загружаются
  в Storage и локально заменяются прямыми ссылками — localStorage больше не
  распухает, а фото видны всем устройствам и пользователям.
- **Стартовые данные**: при первом входе с устройства всё локальное содержимое
  мержится с серверным (pull перед push) и отправляется обратно — регистрация
  со второго устройства ничего не затирает.

## Известные ограничения v1

- Пароль не восстановить (нет email). Ник — только латиница/цифры/`_ . -`.
- Конфликт одновременных правок одного поля — last-write-wins (побеждает
  последняя синхронизация); гараж/журнал/покупки сливаются поэлементно.
- Удаление чужой добавленной позиции локально не распространяется на сервер
  (удалять свои строки может только автор — так настроен RLS).
- Правки **базовых** полей каталога (применяемость, аналоги и т.п.) остаются
  прерогативой владельца data-файлов; синхронизируется «народный слой»:
  заметки, цены, ссылки, фото, статусы, свои позиции.
- Лимиты бесплатного плана Supabase: 500 МБ БД, 1 ГБ Storage, 50 000
  ежемесячных активных пользователей — для сообщества каталога с запасом.
