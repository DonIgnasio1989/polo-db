# Релиз 1.8.4 — мобильные фиксы: «Сохранить» VIN, двойная лупа, отклик кнопок

Дата: 2026-10-18. Исправления по жалобам владельца: «на телефоне некоторые кнопки
лагают или не нажимаются (когда вводишь VIN — сохранить не работает); на кнопке
Декодировать задвоение лупы».

## 1. 💾 «Сохранить» в форме VIN не работало (главный баг)

**Причина.** Кнопка `#g_sb` стартует `disabled` и включалась **только** после
успешного нажатия «🔍 Декодировать» (`decG`). Обработчики поля (paste/blur)
лишь нормализовали текст. Ввёл VIN → тап по «Сохранить» = тап по disabled-кнопке
= ничего не происходит. Даже если бы кнопка нажалась, `sGarV()` при `!pGV.ok`
молча делала `return` без сообщения.

Побочные проявления того же бага:
- после сканера QR (`applyScan`) VIN подставлялся в поле, но «Сохранить»
  оставалась неактивной (тост советовал «проверьте и сохраните» — а было нельзя);
- если после декодирования поправить VIN в поле, `pGV` хранил старый VIN →
  сохранилась бы машина с прежним VIN;
- дубликат ключа `gen` в объекле гаража стирал расшифрованное поколение кузова
  (`gen: pGV.gen` перетирался `gen: ''`).

**Фикс (js/app.js):**
- `sGarV()`: VIN берётся прямо из поля `#g_vi`; при отсутствии/устаревании
  `pGV` декодируется **офлайн** через `vD(raw)` (не зависит от сети и API-ключа);
  невалидный ввод показывает ошибку в `#g_re` и гасит кнопку вместо молчаливого
  выхода; дубль-чек и запись идут от VIN из поля.
- `bindUI`: новый обработчик `input` на `#g_vi` → `syncVinState()`: кнопка
  «Сохранить» активируется сразу, как только введён валидный 17-символьный VIN;
  появляется подсказка «✓ VIN корректен — можно сразу сохранить, а «🔍» покажет
  подробности»; `paste`/`blur`-нормализация тоже вызывает `syncVinState()`.
- Правка VIN после декодирования сбрасывает устаревший `pGV`.
- Убран дубликат ключа `gen` (поколение кузова из `vD` теперь сохраняется).

«🔍 Декодировать» осталась опциональным обогащением (подробный разбор,
📦 поиск в базе оснащения) — но больше не является обязательным шагом.

## 2. 🔍 Задвоение лупы на кнопке «Декодировать» (≤480px)

**Причина.** В HTML текст кнопки — `🔍 Декодировать`, а мобильный CSS делал
`#g_db { font-size: 0 }` + `#g_db::before { content: '🔍' }`. Расчёт был, что
`font-size:0` скроет текст и останется только лупа из `::before`. На
Android-браузерах (Chrome font boosting, Samsung Internet) `font-size:0`
ненадёжно скрывает эмодзи → видны обе лупы.

**Фикс.** Текст обёрнут в `<span class="g-db-lbl">`, лупа живёт в HTML
(единственная). Мобильный CSS скрывает подпись через `display:none`
(`#g_db .g-db-lbl`), правила `::before` и `font-size:0` удалены. Добавлен
`aria-label="Декодировать VIN"` — скринридер озвучит кнопку-иконку.
`.bn` — inline-flex с `gap:6px`, поэтому пробел между 🔍 и подписью не нужен.

## 3. ⌨️ Клавиатура перекрывала кнопки модалок (bottom sheet)

На телефоне модалки — bottom sheet (`align-items:flex-end`), футер с кнопками
у самого низа экрана. Форма VIN автоматически фокусирует поле → клавиатура
встаёт поверх кнопок. С Chrome 108 дефолт — `interactive-widget=resizes-visual`:
layout viewport не уменьшается, и `position:fixed`-низ остаётся под клавиатурой
(«Сохранить не нажимается»).

**Фикс.** В viewport meta добавлен `interactive-widget=resizes-content` —
интерфейс корректно сжимается при открытии клавиатуры, футер модалок остаётся
видимым. Safari/Firefox параметр игнорируют (там и так resizes-content-подобное
поведение либо скролл модалки).

## 4. 👆 «Кнопки лагают» — задержка тапа

Добавлено глобальное правило (конец css/app.css):

```css
button, a, input, select, textarea, summary, label, [onclick] {
    touch-action: manipulation;
}
```

Убирает задержку double-tap-to-zoom (~300 мс) на всех интерактивных элементах —
тап срабатывает мгновенно. Зум двумя пальцами продолжает работать.

## 5. Кэш-бастинг CSS

`css/app.css` подключался без `?v=` — при cache-first в SW телефоны могли
до двух загрузок жить со старым CSS (т.е. с двойной лупой). Теперь
`href="css/app.css?v=1.8.4"` (app.js уже имел авто-бастинг
`?v=<appVersion>&ui=<app-ui-ver>`).
