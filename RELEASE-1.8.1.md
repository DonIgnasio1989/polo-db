# Релиз 1.8.1 — «разделы появились, но они пустые»

**Дата:** 2026-10-18 · **Тип:** hotfix загрузки данных (без изменений UI/базы деталей)

## Симптом

После выкладки нового `data/sections.json` (разделы «Электросхемы», «Предохранители 6N1»,
«Реле 6N1», «Провода и клеммы», «Разъёмы и пины») пункты появились в сайдбаре,
но таблицы в них пустые / «найдено: 0».

## Причина (три наложившихся дефекта загрузчика `lAll()`)

1. **`skipFetch` отменял загрузку ВСЕХ файлов.** Если версия в `data/update.json`
   совпадала с записанной локально (`vw_polo_data_ver`), а деталей в кэше > 50 —
   приложение вообще не ходило в сеть. Новый `sections.json` выкладывался без смены
   `appVersion` (1.8.0 → 1.8.0), поэтому клиенты с уже загруженной базой его не видели.
2. **Версия записывалась даже при провале.** `vw_polo_data_ver` ставился, даже если
   `sections.json`/`parts.json` ответили 404 (например, файлы ещё не докачались на
   хостинг) — последующие загрузки навсегда уходили в `skipFetch`.
3. **Пустые локальные строки перекрывали серверные.** Мердж
   `Object.assign({}, server, local)` отдавал приоритет локальной мете из
   `localStorage` (`vw_polo_meta_v1`), включая `rows: []` — серверные таблицы
   затенялись старым пустым скелетом раздела.

Плюс латентный баг: `lMeta()` вызывалась ПОСЛЕ `sMeta()` внутри мерджа —
пользовательские разделы/категории из импорта JSON терялись при каждом перезапуске.

## Исправления (js/app.js)

- `lAll()`: `lMeta()` перенесена в начало (шаг 0) — пользовательская мета теперь
  реально приоритетна и не затирается.
- Ветка `skipFetch`: лёгкие файлы (`sections` / `categories` / `workshops`)
  перечитываются ВСЕГДА, даже при совпавшей версии; тяжёлые `parts*` — по-прежнему
  только при смене версии.
- Мердж вынесен в `_mergeCats()` / `_mergeSections()` / `_mergeWorkshops()` —
  единые правила для обеих веток.
- `_mergeSections()`: локальные `label`/`icon` сохраняются, но **пустые** локальные
  `rows`/`cols` заменяются серверными.
- `vw_polo_data_ver` записывается только при `serverParts.length > 0`.
- `rC()`: справочные разделы (`SEC_TABLE_IDS = Torque, Diagnostics, Wiring,
  WiringFuses, WiringRelays, WiringRef, WiringPins`) всегда рендерятся через `rSec` —
  вместо пустого списка деталей показывается экран «📭 Данные раздела не загружены»
  с кнопкой **«🔄 Обновить данные»** (`forceDataReload()` — сброс `vw_polo_data_ver`
  + перезагрузка).
- `lU()`: диплинк `#/cat/Wiring*` больше не сбрасывается на «Все системы»,
  даже если мета раздела ещё не загружена.

## Версии

- `js/app.js`: `APP_VERSION = '1.8.1'`
- `index.html`: `<meta name="app-ui-ver" content="1.8.1">` (лоадер грузит
  `js/app.js?v=1.8.1&ui=1.8.1` — service-worker cache-first обходится новым URL)
- `data/update.json`: `appVersion: '1.8.1'` + запись в changelog (5 пунктов);
  смена версии гарантирует, что уже задеплоенные телефоны выйдут из `skipFetch`.

## Деплой

Залить **вместе**: `index.html`, `js/app.js`, `data/update.json`,
`data/sections.json` (и остальные файлы из архива `vw-polo-app-1.8.1.zip`).
На телефоне достаточно обычного обновления страницы; если раздел всё ещё пуст —
нажать «🔄 Обновить данные» внутри раздела.
