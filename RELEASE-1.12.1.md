# RELEASE 1.12.1 — «Поиск информации по деталям: что удалось наполнить и что осталось»

**Дата:** 2026-10-24
**Предыдущая версия:** 1.12.0
**Тип:** патч (Z+1) — обновление данных каталога и новый инструмент аудита; схема и формат не менялись, `DN`/`DV` не поднимались.

## Запрос владельца

> «ищи информацию по всем деталям в базе и наполни их, может есть какие-то нюансы»

## Честно о масштабе

В каталоге **4 124 записи**. Пройти каждую внешним поиском за один заход
нереально, а «наполнить» непроверенными данными — хуже, чем не наполнять:
ошибка в моменте затяжки или в интервале ГРМ ломает мотор. Поэтому работа
шла в три слоя:

1. **внутренний аудит** — найти противоречия внутри самой базы (не требует
   внешних данных и не может наврать);
2. **точечное внешнее исследование** — только там, где источник надёжен и
   ошибка критична (интервалы ГРМ, тормозные диски, применимость);
3. **ранжированный план** на остаток — с приоритетами, методами и источниками,
   чтобы наполнение можно было продолжать партиями.

### Главный нюанс аудита: «суперсессии» оказались вариантами по датам

331 пара с общей базой OEM выглядит как цепочки замен (`030 100 098 EX → GX → MX`),
но при разборе выяснилось, что **89 из них — варианты по периоду выпуска**, а не
замены:

```
030 100 098 EX  «Двигатель в сборе с ГБЦ (1.0, 37 кВт)»  F >> 6N-WW065 000  → первая партия 6N1 до осени 1997
030 100 098 GX  то же название                           F 6N-W-065 001>>   → переходная серия 10/1997 – 6/1998
```

Ставить у таких пар поле `sup` («артикул заменён производителем на …») **нельзя** —
обе позиции актуальны, каждая для своего диапазона шасси. Аудит теперь разделяет
пары на `C1 кандидаты в суперсессии` (242) и `C2 варианты по датам` (89),
и именно поэтому `sup` автоматически не проставлялся нигде: направление замены
(какой артикул новее) по буквенному суффиксу достоверно не определяется.

### Второй нюанс: одно название в двух категориях (68 пар)

```
030 905 377   «Датчик детонации»  → Ignition
030 905 377 A «Датчик детонации»  → Engine
036 133 035 A «…»                 → Fuel и Engine (композитный OEM)
030 905 105 A «…»                 → Ignition, а 6N0 905 104 → Engine
```

Практическое следствие: мастер, открыв категорию «Зажигание», не увидит
вторую карточку того же датчика. Это не дубли (OEM разные), но категории
стоит привести к одному виду. Автоматически не правил — решение о том,
где жить датчику, должно быть вашим.

### N2 · Интервал замены ремня ГРМ — 4 записи (`030 109 119`, `030 109 119 F`, `030 198 119`, ТО-3)

В каталоге стояло «Интервал 60.000 км / 4 года» для ремня **1.0/1.4/1.6**.
По данным производителя (repareo.de, раздел по Zahnriemenwechsel VW Polo):

> «Bei der Variante 6N1, 6N2 und beim Polo Kasten 6NF gibt es nur Vorgaben für
> die **Dieselmotoren**, die Intervalle liegen bei **60.000 und 90.000 km**».

То есть жёсткий интервал VW задаёт **только для дизелей**; для бензиновых 6N
регламентного интервала нет. Практика владельцев: 120 000 км или 5 лет
(polotreff.de/forum/t/161506), контроль с 90 000 км (motor-talk.de).

В карточки добавлено предупреждение: «60 000 км / 4 года» читать как
консервативную рекомендацию для тяжёлых условий; осмотр с 90 000 км;
**обязательная замена по возрасту (5–6 лет)** — резина стареет и на стоящей
машине; обрыв = встреча клапанов с поршнями. Существующие строки не
перезаписывались — только дополнены.

### N4 · Тормозные диски: MIN-толщина и обкатка — 8 артикулов

`6N0 615 301 / B / C / D / E`, `JZW 615 301 L`, `6N0 615 601 / A`. У Polo 6N
**четыре варианта передних дисков** (239×10 невентилируемый, 239×18,
256×20 для AFH/AHS, 256×25 для AJV) и два задних (226×10 до F 6N-XY379 991
и 232×9 после, PR 1KP/1KD/1KE) — MIN у каждого свой.

Числа MIN намеренно **не вносились**: данные поставщиков противоречат друг
другу (autodoc.de даёт Ø256/22 мм, teile-direkt.at для 6N1 — Mindestdicke 18,5,
atp-autoteile — 19,0, но уже для Polo 6C1/6R1). Вместо числа в карточках —
правило: MIN выбита на кромке диска, проверять штангенциркулем, при
достижении MIN замена парой (проточка ниже MIN запрещена), новые диски
обезжирить, первые 200–300 км — обкатка без резких торможений.

## 4. Исправлен генератор VIN-базы — `tools/vin_extract.py`

После выпуска 1.12.1 владелец прислал фрагмент боевого `data/vin-db.json`
(9 записей) и оба генератора. Диагноз и доказательства — в `docs/VIN-DB-BUG.md`.

**Первопричина.** В `vin_extract.py` регулярка `VIN_RE` объявляла границей токена
всё, кроме `[A-HJ-NPR-Z0-9]` — то есть буквы **I, O и Q считались разделителями**
(их legitimately нет в VIN). А `vin_candidates()` искал VIN **во всех строковых
полях записи, включая `pr`** — склейку PR-кодов без разделителей. В строке
`…QH0 QA0 Q1A RLA T6V U2B V0A WV1` буква `Q` из кода `Q1A` стала границей, и
следующие 17 символов `1ARLAT6VU2BV0AWV1` были приняты за VIN: проверка модели
прошла, потому что символы 6–8 подстроки попали на код `T6V` → `6VU` → «Polo 6V».

Всё производное от такого «вин-кода» — `model`, `year`, `plant`, `brand`, `body` —
оказалось мусором (год 1980/2008 при `prod_date` 2002/1994, завод Bruxelles для
машины из Martorell), а поиск по VIN в приложении не работал: пользователь
вводит настоящий VIN, база ключуется поддельным.

**Исправлено (8 правок, все помечены в коде `vin_extract 1.1 (ИСПРАВЛЕНО)`):**
границы токена включают весь алфавит; поля `pr`/`trim` исключены из поиска VIN;
имя файла стало первым кандидатом; добавлена `vin_is_real()` (серийная часть —
6 цифр, WMI из списка VW/SEAT/Audi/Skoda); filler ≠ ZZZ даёт предупреждение;
год из источника перекрывает год из VIN; распознаётся VIN с пробелами/дефисами;
в отчёт добавлены счётчики отброшенных кандидатов с причинами.
`make_vin_db_web.py` правок не требует — он только переносит поле `vin`.

**Регрессионный тест** — `tests/test_vin_extract.py` (5 фикстур, 9 проверок):
на одном дампе старый скрипт выдаёт поддельную запись
(`1ARLAT6VU2BV0AWV1 / Bruxelles / Неизвестно`), исправленный — настоящую
(`WVWZZZ6VZ2W012345 / Wolfsburg / Volkswagen`) и честно отбрасывает
внутренние ключи ETKA и чужие модели.

**Версия приложения не менялась** (1.12.1): `vin_extract.py` — офлайн-инструмент
сборки, в веб-бандл не входит и в пяти местах синхронизации не участвует.

**Что осталось сделать владельцу** (без дампа это невыполнимо):

```
python3 tools/vin_extract.py -i "D:\etka-dump" -o ./out --include-donors -v
python3 tools/make_vin_db_web.py -i ./out/vin-db.jsonl.gz -o ../data
node tools/validate-data.js
```

Обратить внимание на строку отчёта `FGST-ключи ETKA без VIN: N` — если N велико,
часть файлов именуется внутренними ключами ETKA, и записи по ним не появятся,
пока настоящий VIN не окажется в имени файла или в его содержимом. Именно так в
текущей базе нашлись 6V-машины, которых нет в `vin-dump/filtered-vins.txt`.
