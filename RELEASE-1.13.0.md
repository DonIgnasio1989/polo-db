## 1. Новый инструмент `tools/vcds_log.py`

Разбирает лог VCDS в структуру и умеет собрать из него запись журнала
обслуживания. Ключевое решение — **не выдумывать расшифровки**:

| Что делает | Как |
|---|---|
| Кодировка | авто-определение cp1251/cp866/utf-8 с эвристикой по кириллице и «кракозябрам» |
| Структура | сессии → блоки (адрес, название, номер детали, компонент/версия, код ПО, WSC, VCID, маркировки, готовность) → ошибки (код, текст, компонент, статус) |
| Статус `NN-PP` | `NN` — elaborator, `PP` — приоритет. Расшифровка **только документированных** значений (таблица G. Speek + Ross-Tech VCDS Tour). `35` в таблице источника пустой → парсер пишет «⚠ не документирован», а не придумывает перевод |
| Контроль локализации | если в русском тексте статуса зашит другой номер («потерян23» при поле `35-10`) — выдаётся предупреждение |
| Контроль полноты | «6 Ошибок найдены» сверяется с реально разобранными; у кода без строки статуса — предупреждение |
| Компонент | `(F96)`, `(N139)`, `(N183)` вырезаются из текста в отдельное поле |
| Приоритет | расшифровывается только 0–8; `10` у блоков без Freeze Frame (KWP-1281) приоритетом не является — так и помечается |
| `--journal` | запись журнала в формате `sLog()` из `js/app.js`; соседние сессии одного файла склеиваются (порог `--gap`, по умолчанию 360 мин): один визит = одна запись |
| `--md`, `--all` | человекочитаемый отчёт; разбор всего каталога `C:\Ross-Tech\VCDS\Logs` |

Тесты `tests/test_vcds_log.py` — **33 ok** на реальном логе
(фикстура `tests/fixtures/vcds-sample/Log2-sample.txt`), включая проверку
идемпотентности и того, что 35 не расшифрован как факт.

```bash
python3 tools/vcds_log.py -i "Log2-М271МН62.txt" -o restore/vcds.json --journal --md restore/vcds.md
python3 tools/vcds_log.py -i "C:/Ross-Tech/VCDS/Logs" --all -o restore/vcds.json --journal
```

## 2. Справочник «Диагностика»: пятизначные коды VAG

Раздел был только про P-коды EOBD, а на этих машинах сканер показывает
пятизначные коды VAG — то есть ровно то, чего в справочнике не было.

**Добавлена 6-я колонка «Блок / примечание».** Без неё такие коды публиковать
нельзя: один номер означает разное в разных блоках.

| Код | В этом блоке | А где ещё встречается тот же номер |
|---|---|---|
| 00288 | `03-ABS` (ATE 20 IE): выключатель педали тормоза F116/F117 | `25-Иммобилайзер` / `46-Комфорт`: актуатор блокировки рулевой колонки **N360** (Ross-Tech Wiki) |
| 00283 | `03-ABS` (ATE 20 IE): впускной/выпускной клапан контура заднего левого тормоза N139 | современные VAG: датчик частоты вращения переднего левого колеса **G47** (Ross-Tech Wiki) |

Добавлено **6 строк кодов из реального лога** (`01 · 00561`, `01 · 00528`,
`01 · 01072`, `03 · 00272`, `03 · 00283`, `03 · 00288`) и **6 памяток**:
как читать статус `NN-PP`, что значит «не постоянный», почему текст сканера
важнее сводной таблицы, где лежат логи VCDS и чем их разбирать, что значит
«Готовность: не доступна».

Строк в разделе: 100 → **112**. Раздел переименован в
«Диагностика — коды OBD-II и VAG», пункт меню — «Диагностика (OBD/VAG)»
(`VIRTUAL_CATS`). P-коды не пострадали: 6-я колонка у них пустая, ссылки
в 5-й пересчитываются как раньше (для VAG-строк ссылки заданы прямо в строке,
и `enrich()` их больше не затирает).

## 3. Каталог: блоки управления и гидроблок vs электронный блок

Логи VCDS ценны тем, что в них лежит **номер детали блока управления** —
то, чего в каталоге не было вообще. Миграция `tools/migrate-1.13.0.js`
(9 правок в 8 записях, идемпотентна):

| Правило | Что сделано |
|---|---|
| **V1** | Новые карточки `1J0 907 379 G` (электронный блок ABS ATE 20 IE CAN; `Brakes/ABS`, `gens: 6N2`, `v:1`) и `6K0 906 027 E` (ЭБУ Bosch Motronic MP 9.0, `0 261 204 593`; `Engine`, `gens: 6N1/6N2`, `v:1`). В обеих — компонент и код ПО из лога, требование кодирования/базовой установки после замены и коды ошибок с реальными статусами |
| **V2** | Внесена ясность: **614 117 — гидравлический блок, 907 379 — электронный** (источник: ветка Ross-Tech по Golf IV — «ABS pump: 1J0 614 117 C; ABS module: 1J0 907 379 G»). Пояснения добавлены в `6N0 614 117 A/B/C`. **Названия записей не менялись** — ключ слияния в приложении `oem + name`, переименование создало бы «сирот» в IndexedDB |
| **V2** | `1H0 937 503` «Блок управления ABS» помечена ⚠: номер относится к группе 937 (жгуты/разъёмы/реле) и к блокам ABS отношения не имеет — вероятно, название «уехало» при выгрузке из HTML. Запись **не удалена** — до сверки с ETKA |
| **V3** | `1J0 945 511` — выключатель стоп-сигнала (F/F116/F117 для ABS 20 IE), многоконтактный: его отказ даёт ошибки сразу в нескольких блоках. Номер **не подтверждён ETKA** — `v:0` и ⚠ с требованием сверки по VIN. В существующую `1H0 945 515 A` добавлена перекрёстная ссылка |

Каталог: 4 124 → **4 127** записей. Новых расхождений аудит не показал
(`audit-parts.js`: «записей без применимости» осталось 1 071 — у новых карточек
`gens`/`bodies` заполнены).

## 4. Что этот лог говорит про машину (кратко)

| Признак | Вывод |
|---|---|
| ЭБУ `6K0 906 027 E`, MP 9.0, `0261204593` | ⚠ По базам ECU (ecuscb.com, carlabimmo.com, car.gr) номер соответствует **Polo III (6N) 1.4 бензин, 60 л.с.** и платформе Seat 6K/Caddy 9K. Мотор — вероятно AEX, но это **не факт**: словарь приложения относит AEX/AKV к Siemens Simos 2P, значит MP 9.0 стоит на части машин. Точно — только по VIN в ETKA |
| ABS `1J0 907 379 G`, «ABS 20 IE CAN» | ATE ABS 20 IE; связка «гидроблок 614 117 + модуль 907 379» — конец 90-х, на Polo это 6N2 |
| «Готовность: не доступна» | блок не EOBD — диагностика по K-линии |
| «Перенаправление неудачно!» у блока 01 | база данных VCDS (20210928) устарела относительно версии 21.9.0.6 — описания сканер берёт из общей базы и может ошибаться |
| 7 из 9 ошибок — непостоянные | начинать надо со стирания и повторного съёма после поездки, а не с замены деталей |

Приоритет ремонта по этому логу: **00288** (выключатель педали тормоза —
самая дешёвая позиция, три разных статуса по одному компоненту характерны
именно для него) → питание/массы и разъём блока ABS → клапаны контуров →
`01072`/`00528` стереть и наблюдать. Подробности — в `restore/VCDS-LOG-ANALYSIS.md`.

⚠ Это интерпретация, а не диагноз: коды `00528` и `01072` в Ross-Tech Wiki
не описаны вовсе, поэтому опираться можно только на текст сканера и статус.
