# RELEASE 1.10.0 — «У каждой машины свой пробег и свой журнал»

**Дата:** 2026-10-18
**Предыдущая версия:** 1.9.1

## Проблема (запрос владельца)

> «при смене вин карточка моя машина должна переключаться на свой пробег,
> а то получается что журнал ведется на все машины в гараже.»

До 1.10.0 пробег/настройки ТО (`TO`) хранились одним объектом на всё
приложение, а журнал (`LOG`) показывался общим списком: при переключении
VIN в гараже кабинет «Моя машина», виджет ТО в шапке, напоминания, список
покупок и бейджи «🔧 Меняли» продолжали использовать данные одной
(последней настроенной) машины.

## Что сделано

### 1. Пробег и ТО — раздельно по VIN
- Новое хранилище: `vw_polo_to_v1` теперь содержит карту
  `{ "byVin": { "<VIN>": { km, lastDate, interval }, ... } }`.
  Ключ `__common__` — значения, введённые без выбранной машины.
- `TO` — «вид» настроек активной машины; синхронизируется через
  `toSync()` при каждом переключении VIN (`setAV`), добавлении
  (`sGarV`), удалении (`remV`) и на старте (`lTO`).
- Все потребители автоматически стали «per-car»: кабинет «Моя машина»
  (поле пробега, карточка «Ближайшее ТО»), виджет ТО в шапке
  (`rTOWidget`/`nextTO`), напоминание (`toReminderMsg`), список покупок
  (`oShopList`) и печать списка (`pShop`).
- Модалка «🛠 Настройки ТО» подписывает машину (`#tom_car`:
  «· 🚘 …406408» или «· машина не выбрана»); `sTO`/`resetTO` меняют
  данные только активной машины.
- Сброс ТО (`resetTO`) удаляет запись только текущего VIN — чужие
  машины и `__common__` не затрагиваются.

### 2. Журнал — раздельно по VIN
- Каждая запись журнала несёт `vin` (штамповался и раньше, теперь
  используется): `vinLogs()` — записи активной машины, `carLogs()` —
  с учётом переключателя области.
- В журнале появился переключатель **«🚘 Эта машина / 🚙 Все машины»**
  (`SV.logScope`, запоминается). В режиме «все» у записей видны бейджи
  VIN (свой — синий с 🚘, отсутствующий в гараже — с ✝, без VIN —
  «без VIN»).
- Новая запись прикрепляется к активной машине (заголовок модалки:
  «Новая запись · 🚘 …406408»); **правка существующей записи её VIN не
  переписывает** — история не «переезжает» между машинами.
- Кабинет «Моя машина»: последние записи и расходы по годам — только
  своей машины. Счётчик журнала в сайдбаре — тоже.
- У машины без записей — понятная заглушка: «У этой машины записей пока
  нет… В других машинах гаража записей: N» + кнопка «🚙 Показать все».
- Без выбранной машины журнал показывает все записи (с бейджами) и чип
  «машина не выбрана · показаны все записи».

### 3. Бейдж «🔧 Меняли» в карточках деталей
- Индекс `_logByOem` строится по `vinLogs()` — история замен активной
  машины, а не всего гаража. Пересобирается при каждом переключении VIN.

### 4. Гараж
- В превью-строке карточки — чип своего пробега: «🛠 191 500 км»
  (из `TO_ALL[vin]`), видно у всех машин, в т.ч. свёрнутых.
- В тосте переключения VIN — пробег выбранной машины
  («Активный VIN: …406408 · ⚙️ AKV · 🛠 191 500 км»).
- **Удаление VIN из гаража не удаляет его пробег и журнал** — при
  повторном добавлении того же VIN история возвращается.

### 5. Миграция старых данных (автоматически, однократно)
- Старый одиночный формат `{ km, lastDate, interval }` в `vw_polo_to_v1`
  переносится на активный VIN; если машина не выбрана — на единственную
  машину гаража; иначе — в `__common__` (`toMigrateLegacy`).
- Записи журнала без `vin` относятся на активную машину
  (`logMigrateVins`, флаг `vw_polo_logs_vinmig_v1`). Если на старте
  машина не выбрана — миграция откладывается и срабатывает при первой
  активации VIN (`setAV`). До миграции такие записи нигде не теряются:
  без выбранной машины журнал показывает всё.
- Порядок инициализации в `lAll()`: активный VIN валидируется ДО
  загрузки ТО/журнала (от него зависит, кому принадлежат данные).
- Найден и исправлен баг миграции: `toMigrateLegacy` персистит карту
  напрямую (`_toPersist`), а не через `sTOStorage` — иначе
  не-синхронизированный «вид» TO затирал только что перенесённую запись.

## Деплой
1. Залить `index.html`, `js/app.js`, `data/update.json` (+ этот файл).
2. **`data/parts.json` и `data/vin-db.json` на сервере НЕ ТРОГАТЬ** —
   в архиве их нет (только безопасные `parts.full.json`,
   `parts.demo.json`, `vin-db.example.json`, `vin-db.patch.json`).
3. Данные пользователей мигрируют сами при первом запуске 1.10.0;
   серверных миграций не требуется (ТО/журнал живут в localStorage/IDB
   клиента).
