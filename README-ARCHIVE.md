## Два способа применить

**А — патчами (на ваш репозиторий):**
```bash
cd <репозиторий>
for p in patches/*.patch; do git apply "$p"; done
node tests/test_instructions.js && node tests/test_1106.js && node tests/test_sections_1110.js
node tools/build-instructions.js --check --verbose     # 82 записи, 0 ошибок, все артикулы найдены
node tools/build-instructions.js --apply               # 407 карточек / 9 279 строк
node tools/build-parts.js && node tools/dedup.js --src data-src --out restore --apply
node tools/audit-parts.js && node tools/validate-data.js
node tools/check-engines.js                            # S52 R0 A63 O0 N1 X11 (--strict → exit 0; A: IN44/OUT15/CONFLICT4; N1 = AHV — внешних данных не существует)
```

**Б — готовым (без пересборки):**
```bash
cp -r merged-data-src/*  <репозиторий>/data-src/       # уже со слиянием
cp -r server-dist/*      <корень веб-сервера>/         # готовая поставка (23 файла)
```

**В — только SEO-пакет, если репозиторий уже на 1.13.3 (ваш случай):**
```bash
cd polo-db
git apply --check repo-patches/36-repo-live-seo.patch
git apply         repo-patches/36-repo-live-seo.patch
# далее коммит и пуш: canonical/OG начнут указывать на /polo-db/, sitemap станет
# 316 URL, robots.txt закроет материалы разработки и дамп VIN от обхода.
python3 tools/build-sitemap.py --check     # самопроверка: 316 URL, 10 групп ✓
python3 tools/test-build-sitemap.py        # негатив-тест верификатора: 12/12 ✓
```
Патчи 01–35 при этом **не нужны**: они ведут дерево поставки от ваших оригиналов
`uploads/` до текущего состояния, а репозиторий там уже находится.
