# Облегчение поставки: что убрано и почему

Дата: 2026-10-27 · версия приложения: **1.13.1**

Результат — `project/dist/`: **21 файл, 4.0 МБ**, готово к выкладке на сервер.
(13 файлов приложения + `manifest.webmanifest` + 7 файлов в `icons/` — статика PWA и OG-превью.)
(Объём вырос с промежуточных 3.37 МБ после дозагрузки библиотеки: `parts.json` теперь
несёт 11 564 строки инструкций вместо 9 029 — см. раздел 6.)
Смоук-тест пройден: локальный HTTP-сервер на `dist/`, все **22 URL**, которые запрашивает
приложение (включая манифест и иконки), отдают `200`; 6 отсутствующих отдают `404`, и код их
обрабатывает штатно (`vinDbLoad()` и фолбэк каталога обёрнуты в try/catch с проверкой `r.ok`).
`robots.txt` и `sitemap.xml` в dist не входят намеренно — они лежат на вашем сервере.

**Ничего из вашего не удалено**: `uploads/` (87 файлов) не изменён, полное дерево лежит
в `project/`, `dist/` — отдельная папка.

## 2. Что убрано из поставки (3 файла, 2.53 МБ)

| Файл | Объём | Почему можно |
|---|---|---|
| `data/parts.full.json` | 2.83 МБ | **Побайтово идентичен `data/parts.json`** — `build-parts.js` пишет один и тот же `JSON.stringify(out)` в оба имени. Приложение читает его только как фолбэк «чистого локального запуска», когда `parts.json` отсутствует (`js/app.js`, комментарий «Фолбэк для чистого локального запуска / восстановления»). На сервере `parts.json` есть всегда |
| `data/vin-db.filtered-only.json` | 0.23 МБ | **Не запрашивается приложением вовсе**: 0 упоминаний в `js/app.js`, `index.html`, `sw.js`. Это вход для сборки боевого `data/vin-db.json` (13 359 VIN без оснащения), то есть материал разработки |
| `data/vin-db.example.json` | ~1 КБ | Пример формата с одной записью. README VIN-дампа: «Локально, без боевой базы, приложение подхватывает `data/vin-db.example.json` — исключительно чтобы пощупать кнопку». Если выложить его на прод, в модалке «📋 Оснащение» будет висеть пометка «Загружен пример данных» |

### Как вернуть, если нужно

```bash
cp project/data/parts.full.json dist/data/          # фолбэк каталога (+2.83 МБ)
cp project/data/vin-db.example.json dist/data/      # демо оснащения (+1 КБ)
```

`parts.full.json` regenerируется командой `node tools/build-parts.js` — он всегда
идентичен `parts.json`, поэтому держать его на сервере смысла нет.

## 3. Что НЕ вошло в поставку, но должно остаться в репозитории

Это не «мусор», а материалы разработки — их нельзя выкидывать из репозитория,
но и на сервер им не нужно:

| Группа | Зачем нужна |
|---|---|
| `data-src/` (22 файла) | Единственный источник правды для каталога. `build-parts.js` собирает из него `data/parts.json`. **Править каталог нужно здесь, не в `data/`** |
| `tools/` (9 JS) | Цепочка сборки: `build-instructions.js` → `build-parts.js` → `dedup.js` → `audit-parts.js` → `validate-data.js`, плюс `migrate-1.10.6/1.12.1/1.13.0.js` и `build-analogs.js` |
| `tools/instructions/` (9 файлов) | Библиотека инструкций — данные, а не код. Именно она дала +6 744 строки в каталог |
| `tests/` | 142 проверки. Без них релизный чеклист из «памятки» не выполняется |
| `restore/` | Журнал изменений. `data-fixes-*.json` и `DATA-FIXES-*.md` — **единственная история трёх миграций** (570 + 22 + 8 правок). Патчи 03–05 защищают её от затирания |
| `vin-dump/` | `filtered-vins.txt` (13 359 VIN) нужен `validate-data.js` — блок «VIN sanity» сверяет 9-ю позицию с `filtered-files.txt`. Без них валидатор даст предупреждение |

### Чего на сервере нет и как приложение на это реагирует

| Файл | Реакция приложения |
|---|---|
| `data/vin-db.json` | `vinDbLoad()` получает не-`ok` → пробует `vin-db.example.json` → тоже не-`ok` → `VINDB.map` остаётся пустым. Модалка «📋 Оснащение» показывает «Данных об оснащении нет». **Так и задумано**: боевая база живёт на вашем сервере, архив не должен её затирать |
| `data/vin-db.patch.json` | Есть в dist. Грузится **всегда** и имеет приоритет над основной базой |
| `robots.txt`, `sitemap.xml` | В dist **не входят** по решению владельца (файлы уже на сервере). `index.html` на них не ссылается — отсутствие в dist ничего не ломает |
| `data/parts.demo.json` | Не запрашивается, пока есть `parts.json` |
| `data/parts-01…05-*.json` | Запрашиваются только модалкой «Обновление базы» (`checkUpdate()`) для сравнения «что изменилось». Отдадут 404 — модалка покажет пустое сравнение, каталог при этом работает |

Если хотите, чтобы модалка «Обновление базы» показывала честное сравнение, доложите
`data/parts-01…05-*.json` (+0.36 МБ). На основную работу приложения они не влияют:
`update.json → files[]` содержит только `data/parts.json`.

|---|---|---|
| Размер файла | 0.89 МБ | **2.83 МБ** (×3.2) |
| Карточек с инструкциями | 1 729 из 4 127 | 1 847 из 4 127 |
| Всего строк инструкций | 2 285 | **11 564** |
| — `proc` (процедуры) | 66 | **3 844** (×58) |
| — `tool` (инструмент) | 13 | **1 090** (×84) |
| — `spec` (спецификация) | 1 360 | 2 592 |
| — `warn` (внимание) | 260 | 2 581 |
| — `note` (заметки) | 567 | 1 383 |
| — `rec` (рекомендации) | 19 | 74 |

Процедур и инструмента в каталоге практически не было — библиотека закрыла именно этот
провал. Плата: +1.9 МБ к файлу, который телефон скачивает при первом запуске и держит
в кэше service worker.

**Что с этим можно сделать, если 2.8 МБ много:**

1. Включить gzip/brotli на сервере. Текст сжимается хорошо: JSON без отступов, много
   повторяющихся строк — ожидаемо 3–5×, то есть ~0.6–0.9 МБ по сети.
   `sw.js` при этом ничего не ломает: он кэширует то, что отдал сервер.
2. Не отдавать `data/parts.full.json` (уже сделано — его нет в dist).
3. `update.json` грузится с `cache: 'no-store'` каждый запуск — 71 КБ, из них 41 КБ
   changelog. См. раздел 4.

## 7. Как пересобрать `dist/` с нуля

```bash
cd project
node tools/build-instructions.js --check --verbose   # 0 ошибок, 0 предупреждений
node tools/build-instructions.js --apply             # 407 карточек / 9 279 строк (82 записи библиотеки)
node tools/build-parts.js                            # data-src → data/parts.json (+validate +analogs)
node tools/dedup.js --src data-src --out restore --apply
node tools/audit-parts.js
node tools/validate-data.js                          # 0 ошибок

rm -rf dist && mkdir -p dist/js dist/css dist/data dist/icons
cp index.html sw.js manifest.webmanifest dist/
cp js/app.js dist/js/ && cp css/app.css dist/css/
cp icons/* dist/icons/                          # статика PWA и OG-превью
for f in update.json parts.json categories.json sections.json analogs.json \
         workshops.json pr-codes.json pr-codes-ru.json vin-db.patch.json; do
    cp data/$f dist/data/
done
du -sh dist && find dist -type f | wc -l             # ~4.0M, 21 файл
```
